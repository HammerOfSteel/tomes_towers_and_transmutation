# Cave & Glade Integration
> ⚠️ GAP — Place cave and glade entrances on the realm overworld map.

## Status: 🚧 In Progress — CG-1, CG-2, CG-3 done as pure/tested modules (not yet wired into `OverworldScene.ts`)

## Goal
Caves and glades generated by OW-C appear as entrance props on the overworld. Caves are in mountain/bog biomes; glades are in forest biomes.

## Implementation notes (this session)

Following the same "pure bridge module" pattern used for settlement/dungeon
integration: each piece is a standalone, fully unit-tested module with **zero**
changes to `overworld-studio.ts` or the live `OverworldScene.ts`. Wiring these
into the actual renderer/scene-graph remains the single deferred step, shared
with the settlement and dungeon integration work.

**Deliberate deviations from the literal spec** (documented in file headers):
- `RealmBiome` has no `mountain` or `bog` value (10 biomes: `deep_ocean | ocean
  | beach | desert | savanna | grassland | forest | taiga | tundra | snow`).
  `CaveGladePlacer.ts` substitutes an elevation threshold
  (`CAVE_ELEVATION_THRESHOLD = 0.7`) OR `tundra`/`taiga` biome as the
  "mountain/bog-like" eligibility test for cave placement.
- The Studio's pre-existing **local** `CaveBiome`/`GladeBiome` types (used by
  its separate cave/glade *interior floor* designer, module-private in
  `overworld-studio.ts`) are a different taxonomy from CG-1's spec
  (`crystal|lava|ice|fungal|ancient`) and are intentionally left untouched —
  `CaveGladePlacer.ts` defines its own exported `CaveEntranceBiome` type
  matching the TODO's literal wording instead.
- `RealmData` is **not** extended with `caves`/`glades` fields (would require
  editing the large, DOM-coupled `overworld-studio.ts`). Instead
  `placeCavesAndGlades()` operates on `RealmTerrainInput` (the same terrain
  grid shape already used by `RealmToTerrain.ts`/`RealmRiverMesh.ts`) and
  returns its own `CaveMarker[]`/`GladeMarker[]`, ready for a future step to
  merge into the live world-gen pipeline.

### CG-1 — Cave Entrance Prop ✅ (`src/world/CaveEntranceBuilder.ts`)
- [x] `buildCaveEntrance(biome): BuiltCaveEntrance` — rocky mound (icosahedron)
      around a dark circular opening, with biome-tinted accent chunks
- [x] Biome variants: crystal (glowing cyan, emissive), lava (glowing orange,
      emissive), ice (pale cone accents), fungal (mossy green, faint glow),
      ancient (carved stone, no glow)
- [x] `isNearCaveEntrance()` — 2 WU trigger-radius check for an "[E] Enter
      Cave" prompt (prompt UI itself is out of scope — no existing prompt
      widget API to hook into yet)
- Tests: `tests/world/CaveEntranceBuilder.test.ts` (10 tests) — one per
  biome, determinism, emissive-material check for crystal/lava, trigger
  radius edge cases.

### CG-2 — Glade Entrance ✅ (`src/world/GladeEntranceBuilder.ts`)
- [x] `buildGladeEntrance(): BuiltGladeEntrance` — two mossy stone pillars, a
      ring of 8 mushrooms, a translucent vertical light shaft
- [x] Ambient particle system (24 drifting points, "fireflies/spores") with an
      `update(deltaSeconds)` method the caller drives from its render loop
- [x] `isNearGladeEntrance()` — 2 WU trigger-radius check, same pattern as
      caves
- Note: unlike caves, the spec gives glades no biome/faction variant, so
  `buildGladeEntrance()` takes no parameters (single fixed look).
- Tests: `tests/world/GladeEntranceBuilder.test.ts` (7 tests) — structure,
  particle count, animation step, particle wrap-around, trigger radius.

### CG-3 — Realm Map Placement ✅ (`src/world/CaveGladePlacer.ts`)
- [x] `placeCavesAndGlades(input, options)` — deterministic (seeded)
      placement of `CaveMarker[]` (x, y, seed, `CaveEntranceBiome`) and
      `GladeMarker[]` (x, y, seed) over a `RealmTerrainInput` grid
- [x] Caves: 2-4 by default, eligible cells = elevation ≥
      `CAVE_ELEVATION_THRESHOLD` OR biome is `tundra`/`taiga`
- [x] Glades: 1-3 by default, eligible cells = biome is `forest`/`taiga`
- [x] `minSpacing` enforced between all placed markers (caves and glades
      share the same spacing pool); optional `avoid` list lets a caller keep
      markers clear of existing settlement/dungeon positions
- [x] No markers ever placed on ocean/water cells (excluded by the
      biome/elevation eligibility checks above)
- Tests: `tests/world/CaveGladePlacer.test.ts` (9 tests) — determinism,
  count ranges (default and explicit), biome eligibility for both cave and
  glade markers, spacing enforcement, `avoid`-list exhaustion, valid
  `CaveEntranceBiome` + seed on every cave marker.
